# MDL-87490 — Reverting assignment submission to draft grants an additional attempt

**Reproduction status:** `confirmed` in one controlled browser trial on Moodle 5.3.1.

**Requirement:** [REQ-ASG-08](../srs/modules/assignment.md#req-asg-08--reverting-an-ungraded-submission-to-draft).

**Upstream:** [Moodle tracker][tracker] and [issue API][issue-api].

The upstream issue is open, lists Moodle 4.5.7 and 5.1.1 as affected, and records no fix version. A Moodle triager confirmed the report. The 5.3.1 finding below comes from the local run.

## Environment and fixture

The local run used Moodle 5.3.1 (Build 20261112, database version `2026100501.00`), official tag `v5.3.1` at `cfe123f26fc7071981fe949cb16cd5a08a8234f1`. The running container’s version metadata, assignment implementation, assignment schema, and file plugin matched the checked-out files byte-for-byte. Use the [Issue #8 Docker Compose stack](../../infra/README.md) with PHP 8.3 and PostgreSQL 17. From the repository root, use the documented local environment file, then run:

```sh
docker compose --env-file infra/.env -f infra/docker-compose.yml up -d
docker compose --env-file infra/.env -f infra/docker-compose.yml ps
./infra/sample-data/load.sh
```

Open the configured Moodle URL (default `http://localhost:8000`). Use two separate browser profiles or sessions. In CS101, sign in as `student1` (enrolled student with `mod/assign:submit`) and `teacher1` (editing teacher with `mod/assign:grade`). Take passwords from the local environment. The editing teacher also needs permission to add the activity when preparing the fixture.

Create a new assignment in CS101 named **MDL-87490 Trial A**. Do not reuse the course's seeded Assignment 1. Use an attachment named `mdl-87490.txt` containing the single line `MDL-87490 file submission fixture.`.

| Setting | Value |
| --- | --- |
| Availability | Disable Allow submissions from, Due date, Cut-off date, and the submission time limit. Use no user overrides, extensions, or locks. |
| Submission types | File submissions only. One file, 1 MB, unrestricted file types. |
| Submission settings | Require students to click the submit button **Yes**. Require that students accept the submission statement **Yes**, with a nonempty site statement. Allowed attempts **Unlimited**. Grant attempts **Automatically**. |
| Groups and grades | Individual submission, no blind marking or marking workflow, points out of 100. Leave the student's grade unset. |

## Reproduction

1. As `student1`, open **MDL-87490 Trial A**. Choose **Add submission**, upload the fixture file and save. Verify that the draft still offers **Edit submission**.
2. Choose **Submit assignment**, accept the statement and choose **Continue**. Verify the submission is **Submitted for grading** and the original file is shown.
3. As `teacher1`, open **Submissions**. The verified path from the authenticated teacher session is `/mod/assign/view.php?id=<course-module-id>&action=grading`. Find `student1` and open the three-dot **Submission actions** menu beside the submission status. Choose **Revert the submission to draft** exactly once. Leave the grade unset and avoid the actions in the grade column. [Navigation][gradingnav] · [Row action][rowaction]
4. Refresh the student tab. Check the current attempt number and status, the available buttons, and the original submission in **Previous attempts**.

**Expected:** Attempt 1 is an editable draft and remains current, with its file intact. The student can edit or replace the file and resubmit attempt 1. The revert does not consume another attempt.

**Observed on 5.3.1:** Before reversion, attempt 1 was submitted for grading with one file and no grade. After reversion, the student view showed attempt 2 as **Reopened** and offered **Add a new attempt** and **Add a new attempt based on previous submission**. The original file remained on attempt 1 in **Previous attempts**, where attempt 1 was a draft. The student had no direct edit or remove action for attempt 1.

The teacher route returned HTTP 200 after the browser's original **Submissions** link locator failed to resolve. The browser used the submission row's revert action alone.

**Sanitized access-log record.** Trial A used course-module ID `2`. The revert occurred at `2026-11-22T15:06:45Z`. Within two minutes of that timestamp, the assignment access log showed the following requests.

| Request | Count | HTTP status |
| --- | ---: | --- |
| GET assignment view without an action | 3 | 200 |
| GET `action=grading` | 2 | 200 |
| GET `action=reverttodraft` | 1 | 303 |
| `action=addattempt` | 0 | — |
| POST to assignment routes | 0 | — |

| Point in trial | Stored attempt | Status | Current (`latest`) | Files |
| --- | --- | --- | --- | --- |
| Before revert | 0 (UI attempt 1) | `submitted` | 1 | 1 |
| After revert | 0 (UI attempt 1) | `draft` | 0 | 1 |
| After revert | 1 (UI attempt 2) | `reopened` | 1 | 0 |

Read-only database inspection also found a grade placeholder of `-1` on stored attempt 0 after revert. The UI showed **Not graded**.

## Technical explanation

1. **Revert** requires `mod/assign:grade`, sets the existing submission to `draft`, invokes plugin revert hooks, and calls `update_grade()` to record the grader and modification. When there is no grade row, `get_user_grade()` creates a placeholder with `grade = -1`. [Revert][revert] · [Placeholder][ungraded]
2. **Grade update** checks that the grade corresponds to the latest attempt, then calls `reopen_submission_if_required()`. The Automatic branch sets `$shouldreopen = true` without testing whether a grade was assigned. Unlimited attempts bypass the cap. [Grade update][gradeupdate] · [Reopen policy][reopen]
3. **New attempt** creates a submission row at `attemptnumber + 1` in `reopened` status. The student action menu offers a new blank submission or a copy of prior work for a reopened attempt and omits the remove action. [New attempt][addattempt] · [Student action menu][menu]

## Live demo

The browser sequence was verified once on the Issue #8 stack. Allow 1–2 minutes after setup.

1. Verify the Compose services and open separate sessions for `teacher1` and `student1`. Pre-stage a fresh assignment with the settings above and one submitted, ungraded file. The empty **MDL-87490 Trial B** is available on the tested local stack. In the teacher session, open the grading page by the URL in step 3 above.
2. Show the student's attempt 1 with its file and **Not graded**. In the teacher tab, open the three-dot menu beside the status and choose **Revert the submission to draft**. Leave the grade column untouched.
3. Refresh the student tab. Show attempt 2 as **Reopened**, then expand **Previous attempts** if needed to show the original draft and its retained file. The expected view would still have attempt 1 current and editable.

**Reset:** Create a fresh assignment with the same settings and a unique name, then submit the same file as `student1`. Keep prior trials intact.
