# MDL-85503: Course category view hides categories of enrolled courses

Ticket: [MDL-85503](https://moodle.atlassian.net/browse/MDL-85503) "Course Category View - End users do not see categories for enrolled courses" (component *Course*, status *Open*, reported against 4.3 to 5.0).
Reproduced on **Moodle 5.3.1** (`v5.3.1`, commit `cfe123f2`) in the Docker Moodle of `infra/`, on 2026-11-22. The bug is still present in 5.3.1.

> **Module note.** Issue #14 lists this bug under grading, but the ticket is about course categories and the front page, not grades. It belongs to the *Courses & enrolment* module (course categories are in its scope). It is documented here as the issue asks; the owner of the course module should be told.

## What the ticket says
A site can show students either all categories and courses, or only the courses they are enrolled in. There is no option to show *categories that contain the courses a student is enrolled in*. The capability `moodle/category:viewcourselist` is meant to control this, but when it is removed for end users, the front page items **List of categories** and **Combo list** (and the category page) show nothing at all, where they should show the enrolled courses and their categories.

## Steps to reproduce
Manual (Moodle UI, as admin, then as `student1`):
1. Start Moodle and load the sample data ([infra/README.md](../../infra/README.md)). `student1` is enrolled in CS101 and CS201 (category *Engineering*); `MATH101` is in the same category.
2. The front page only exists for logged-in users if the site home is switched on. In the infra image it is off and the default home page is the Dashboard, so set the settings `enablemyhome` = 1 (site home on) and `defaulthomepage` = 0 (*Home*), for example with `php admin/cli/cfg.php --name=enablemyhome --set=1` inside the container.
3. *Site administration → Front page → Front page settings*: set **Front page items when logged in** to **Combo list**.
4. *Site administration → Users → Permissions → Define roles → Authenticated user*: set the capability `moodle/category:viewcourselist` to **Prevent** (system context). This is the documented way to stop everybody from browsing all courses.
5. Log in as `student1` and open the home page (`/`) and `/course/index.php`. Log in as `admin` and open the same pages.

Automatic: `python docs/bugs/MDL-85503/reproduce.py` does steps 2-5 for three setups and puts every setting back at the end (needs Python 3.8+ and Moodle running; output in [`results.txt`](MDL-85503/results.txt)).

## Expected and actual behaviour

| Setup | User | Expected | Actual (Moodle 5.3.1) |
|---|---|---|---|
| Permission allowed (default), Combo list | `student1` | Category and courses | *Engineering* with all three courses, including MATH101 where the student is not enrolled |
| Permission prevented, Combo list | `student1` | *Engineering* with CS101 and CS201 (the enrolled courses) | Section **not shown at all**; `/course/index.php` answers **HTTP 404** |
| Permission prevented, List of categories | `student1` | *Engineering* | Section **not shown**; `/course/index.php` **HTTP 404** |
| Permission prevented, Combo list | `admin` | everything | everything (works) |

The category page by id (`/course/index.php?categoryid=2`) also answers HTTP 404 for the student in this setup. So a student cannot use categories to navigate to a course they are enrolled in, while an admin can.

## Where it comes from
- `core_course_category::can_view_category()` allows a category only with `moodle/category:viewcourselist` in that category's context ([`course/classes/category.php#L684`](https://github.com/moodle/moodle/blob/v5.3.1/public/course/classes/category.php#L684)). Enrolment is not considered.
- The front page lists ask for the children of the top category, which only contains categories the user may view, and return nothing when there are none: `frontpage_combo_list()` ([`course/renderer.php#L1378`](https://github.com/moodle/moodle/blob/v5.3.1/public/course/renderer.php#L1378)) and `frontpage_categories_list()` ([`#L1406`](https://github.com/moodle/moodle/blob/v5.3.1/public/course/renderer.php#L1406)). Both carry `TODO MDL-10965 improve`.
- `/course/index.php` takes `user_top()` and throws `cannotviewcategory` when the user has no viewable category ([`course/index.php#L43`](https://github.com/moodle/moodle/blob/v5.3.1/public/course/index.php#L43), [`#L59`](https://github.com/moodle/moodle/blob/v5.3.1/public/course/index.php#L59)). `user_top()` has the open item `TODO MDL-10965 find ANY/ALL categories in the tree where user has access to` ([`category.php#L330`](https://github.com/moodle/moodle/blob/v5.3.1/public/course/classes/category.php#L330)).

## Requirement for the new system
The new system must not copy this behaviour: a user sees a category in the category view if the category is visible to them **or** it contains a course they are enrolled in, and under it only the courses they may access. Suggested requirement for the course module (ID to be agreed with its owner): *"The category view shows the categories of every course the user is enrolled in, even when the user may not browse all courses."* Golden master: the same enrolments in Moodle and in the new system; Moodle shows nothing (bug), the new system shows the enrolled courses, so this difference is intentional and must be written in the SRS.
